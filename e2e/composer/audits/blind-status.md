# Blind Composer status audit

Independent visual audit, 2026-10-06. No earlier audit, checklist, PR conclusion, or other auditor result was read. No implementation or Paper changes were made.

## Evidence and scope

Primary design: [Argo / Session](https://app.paper.design/file/01M44G6AG3HPXGPPPMKS9S3H8J/p-3-0), file `01M44G6AG3HPXGPPPMKS9S3H8J`, token hash `2737d693` before and after inspection. Read Paper's guide, basic info, tokens, trees, JSX and computed styles. Screenshots verified the designs; expected measurements below come from JSX/computed styles, not screenshot estimation.

Inspected Composer masters: Components / Composer, Plan and context rows, New Session, Main checkout; ContextWindow, UsageLimits, PlanSteps and desktop Popover / phone Sheet wrappers. Inspected actual Session copies: desktop Composer `6DH-0`, inspector-closed Composer `QCK-0`, and phone Composer `2461-0`. Exact design exports are saved beside the browser evidence in `screenshots/status/paper-*.json`.

Rendered the real component at `localhost:6008`, story `sessions-composer--overview`, at 1440×900 and 390×844, Default theme in light and dark. Exercised the New worktree label and Switch, Base branch and Checkout triggers, Plan, Context, Usage, Escape dismissal and Compact. All browser actions used CUA in temporary hidden tabs. Restored the Storybook appearance to Light, reset the viewport and closed both created tabs.

The complete `screens-sessionscreen--overview` story renders only “Session / session-running”; `SessionScreen.tsx:9` is a placeholder. This audit therefore proves the actual Composer component and mocks, not its integration into a complete Session screen. The Composer presentation story adds `p-4` at `Composer.stories.tsx:32`: at a 390px viewport its card is 358px wide, whereas the Paper phone Session card is 374px. This wrapper difference must not be mistaken for a component width failure.

Fonts were awaited with `document.fonts.ready` and observed `loaded`. AX observation followed each action. The 150ms enter animations had `transform: none` by measurement; Switch off was observed at its final `transform: none`. Spinner motion was verified from its infinite 0.75s animation and different rotation matrices in separate measurements. The CUA DOM bridge does not expose `document.getAnimations()`, so a finite-animation promise wait was unavailable; observable final geometry was used instead. Font-family CSS was measured, but the browser's actual glyph face was not independently identified.

## User overrides that passed

- Branch display is lowercase `main` in both Switch states, and the shared control formats branch strings with `toLowerCase()` (`ComposerConfiguration.tsx:818`). The observed mock provides `main`; an uppercase source branch was not driven through the browser in this audit.
- New worktree uses the shared reusable Switch, `size="small"`: measured **26×16** track, **12px** thumb. Clicking the label changed aria-checked true→false and disabled Base branch; clicking the Switch restored true. The label interaction and requested smaller reusable control are implemented.
- Usage popup/sheet has **no subtitle** in all four rendered modes. Paper still contains the account-description subtitle; its omission is intentional per user override.
- In-progress Plan is a **real monochrome animated spinner**, 0.75s infinite linear. Its strokes resolve to #737373 in light mode. Two independently captured rotation matrices differ. Do not replace it with the static Paper arc.
- Context count is **single line** (16px tall); desktop used and capacity pieces share the same y. Phone shows only used count. The ring's track and colored arc are visible in light and dark. Compact closes the surface and visibly changes34k→12k in the mock.
- Popups/sheets have **no blue focus outline**. Popup computed outline style is none, and focus treatment after Escape is neutral gray on the trigger. Desktop popup radius10, border1, widths420 /320 /320 and Paper's two-part shadow match.

## Paper drift, tokens and product coverage

The desktop Session Checkout **copy** (`6EX-0`, and inspector-closed `QCK-0`'s footer) exports the **tree** vector starting `M160 112h48…`. The Composer / Context bar **master** exports the **git-branch** vector starting `M232 64…`. This is master-copy drift, not an implementation failure: the implementation's GitBranchIcon follows the master. The drift is saved in `paper-6EJ-0.json` against `paper-344-0.json` / `paper-24AJ-0.json`.

Other inspected Plan/Context/Usage copy structures match their content masters apart from permitted widths, text and hidden phone labels. Phone Sheet content widths358 versus desktop286/386 are intentional. The actual Session mobile tray matches the phone row master structure. Only light Paper artboards were available in the inspected Session designs. Dark browser colors were checked against the code's dark tokens; visual dark-Paper parity is **unverified**.

Rendered active token values agree for light foreground #0a0a0a, muted #737373, border #e5e5e5, success #00a63e, spacing4/6/8/12/16, radii6/8/10/14 and font sizes12/14/20 with16/20/24 line heights. The stylesheet's `--font-sans` fallback string differs from Paper after its shared SF Pro Text primary family (Paper includes BlinkMacSystemFont/system-ui; code additionally includes Segoe UI/Roboto/Helvetica/Arial). Browser normalizes this to a platform-dependent computed string; no macOS glyph mismatch is claimed. Literal Paper fractional token aliases such as `--spacing-0_5`, `--leading-4_5`, `--leading-5_5` are absent from `tooling/uniwind/theme.css`; rendered utility values can still match. This is token-name drift, not proof of a visible difference in every control. Full token export is `paper-tokens.json`.

The content masters are named ContextWindow, UsageLimits and PlanSteps; these are embedded in ComposerStatus rather than independently rendered named components/stories. This is a master-to-code naming/coverage difference under `docs/agents/paper.md`, not a demand to add duplicate appearances. The interactive Composer story does expose their normal popup/sheet content.

Phone Subagents/Shells are present with14px icons, 12px/16px counts and the running Subagent count in success green, matching the optional Paper work-count treatment. Their supplied callbacks are no-ops in the mock, so opening real work surfaces is **unverified**. Disabled and Sending variations visibly disable all scoped controls on desktop. Native iOS/Android sheets, safe-area layout, swipe dismissal, tactile interaction, long counts, warning Context states and full Session integration were not verified. Shell/editor/toolbar/menu internals and branch-popup interiors were excluded.
