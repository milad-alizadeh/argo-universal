# Feed streaming motion

Argo can take three ideas from other coding agents. Keep settled text in place, preserve each reveal’s progress across updates, and let the reader control whether the Feed follows new content. The strongest references are Codex for Markdown, VS Code for reveal timing, and OpenCode for scroll anchoring.

## What the apps do

| Reference | First-party evidence | Application to Argo |
| --- | --- | --- |
| Codex terminal | Commits settled lines to scrollback and renders one disposable preview of unfinished prose. It holds syntax such as an unfinished link destination and tables whose widths can change. The commit scheduler speeds up when the queue grows or ages. [Stream controller](https://github.com/openai/codex/blob/6d9f0199ed0cfdd184754e593e0625917ad0ca28/codex-rs/tui/src/streaming/controller.rs#L1-L43), [prose preview](https://github.com/openai/codex/blob/6d9f0199ed0cfdd184754e593e0625917ad0ca28/codex-rs/tui/src/streaming/prose_preview.rs#L1-L17), [scheduler](https://github.com/openai/codex/blob/6d9f0199ed0cfdd184754e593e0625917ad0ca28/codex-rs/tui/src/streaming/chunking.rs#L1-L43) | Keep settled blocks mounted and limit the part of the Markdown tree that can change. Catch up quickly after bursts and flush the exact response when it ends. |
| VS Code Copilot Chat | Its experimental incremental renderer remembers which Markdown children have appeared and when the active batch began. If it replaces a child, a negative animation delay resumes the reveal at the elapsed time. Its default reveal changes only opacity and honors reduced motion. [Incremental renderer](https://github.com/microsoft/vscode/blob/36e8c0289a5f29eae15a933263220d9895302ff6/src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatIncrementalRendering/chatIncrementalRendering.ts#L272-L301), [animations](https://github.com/microsoft/vscode/blob/36e8c0289a5f29eae15a933263220d9895302ff6/src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatIncrementalRendering/animations/blockAnimations.ts#L27-L49), [timing tests](https://github.com/microsoft/vscode/blob/36e8c0289a5f29eae15a933263220d9895302ff6/src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatIncrementalRendering.test.ts#L377-L459) | Give new text a stable identity and start time. Further appends and the transition to settled content should leave existing glyphs at their current opacity. |
| Gemini CLI | The source attributes terminal flicker to rerendering growing messages. It commits sections at safe Markdown boundaries, maintains one pending row, and batches scroll updates with distinct anchors for end-following and reading history. [Stream handler](https://github.com/google-gemini/gemini-cli/blob/4f343cabc7b59ab990d7411e920094108524abff/packages/cli/src/ui/hooks/useGeminiStream.ts#L1238-L1295), [Markdown split](https://github.com/google-gemini/gemini-cli/blob/4f343cabc7b59ab990d7411e920094108524abff/packages/cli/src/ui/utils/markdownUtilities.ts#L93-L124), [scroll handling](https://github.com/google-gemini/gemini-cli/blob/4f343cabc7b59ab990d7411e920094108524abff/packages/cli/src/ui/components/shared/VirtualizedList.tsx#L598-L646) | Preserve row identity and batch layout corrections. Choose either the end or the reader’s visible row and offset as the anchor for each update. |
| OpenCode | The terminal keeps one Markdown renderer through completion and applies the final text before ending streaming. The web virtualizer batches size changes and preserves the visible anchor during touch momentum on iOS browsers. [Terminal text part](https://github.com/anomalyco/opencode/blob/d412042beb9821ed61c73466406f7dbfdadc04e0/packages/tui/src/routes/session/message-parts.tsx#L174-L200), [web virtualizer](https://github.com/anomalyco/opencode/blob/d412042beb9821ed61c73466406f7dbfdadc04e0/packages/app/src/session/timeline/virtualizer.tsx#L388-L503) | Keep completion in the same row and test scroll corrections during an iOS gesture, when multiple measurements can arrive together. |
| Continue and Cursor | Continue suspends following when the reader scrolls away, then resumes on returning to the end or on a new prompt. Cursor’s release notes describe gliding to new text and tool cards while following. [Continue scroll hook](https://github.com/continuedev/continue/blob/5522c6f44ca0ac3528b37244818fbfa39b5af470/gui/src/pages/gui/useAutoScroll.ts#L4-L54), [Cursor release notes](https://prod.cursor.com/docs/release-notes#:~:text=Smoother%20scrolling%20while%20an%20agent%20streams) | If Argo still makes abrupt intentional moves after layout is stable, test one scroll animation that can take a new destination and stops when the reader takes over. |
| Zed and Claude Code | Zed coalesces text arriving during a background Markdown parse and reuses highlighting for unchanged fenced code. Claude Code documents visible-only rendering and a fixed prompt in fullscreen mode. [Zed parser](https://github.com/zed-industries/zed/blob/761786a4ef7144de734e48cb2e8f99bc46b5061e/crates/markdown/src/markdown.rs#L1246-L1286), [Zed highlighting test](https://github.com/zed-industries/zed/blob/761786a4ef7144de734e48cb2e8f99bc46b5061e/crates/markdown/src/markdown.rs#L5874-L5895), [Claude Code fullscreen](https://code.claude.com/docs/en/fullscreen#what-changes) | Check which work repeats during a burst before adding another animation loop. |

ChatGPT’s November 2024 web release notes describe bringing the start of a new conversation into view and stopping automatic bottom scrolling during generation. That documents a scroll policy for a new conversation on web. The native ChatGPT and Codex fade implementations were outside the evidence available for this review. Argo has already chosen end-following for its Feed in [issue #1874](https://github.com/milad-alizadeh/argo-universal/issues/1874). [ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes#:~:text=Initiating%20a%20new%20conversation%20now%20scrolls%20it%20into%20view)

## What we measured in Argo

- In the standalone Markdown Storybook preview at phone width, the first glyph moved horizontally by 122.7 CSS pixels as the centered block grew. After fixing the column width and anchoring the block at its top leading edge, the glyph held the same x and y coordinates across 306 sampled web frames. The revised preview plays once. This result measures the Markdown fixture’s geometry. [Preview story](../../../packages/kit/src/primitives/content/markdown/markdown.stories.tsx)
- A Storybook replay through the Feed component appended a prompt and a 16-paragraph answer to the Long Feed fixture. At widths of 390 and 1,280 CSS pixels, Chromium emitted 26 scroll events per replay with zero backward steps larger than 2 pixels. Both runs ended exactly at the bottom. This checks append-only following on web. Native scroll, reader detachment, and live transport are still unverified in this replay. [Feed scroll](../../../packages/client/src/features/feed/components/feed/feed-scroll.tsx)
- Unfinished emphasis rendered as plain text in a reproduced case, then changed font when the closing delimiter arrived. The local preview change covers a simple line-leading emphasis opener and keeps code literal. An opener can still turn out to be literal at completion, so a safe Markdown boundary deserves its own test before extending this heuristic. [Streaming text](../../../packages/kit/src/primitives/content/markdown/streaming-text.ts), [unit tests](../../../packages/kit/src/primitives/content/markdown/streaming-text.test.ts)
- The previous iOS clip used a centered and repeating fixture. Native arriving runs currently return plain strings, so their text is immediately visible. Web arriving runs use a 200 ms opacity animation with a reduced-motion setting. [Native run](../../../packages/kit/src/primitives/content/markdown/arriving-run.tsx), [web run](../../../packages/kit/src/primitives/content/markdown/arriving-run.web.tsx), [PR #2395](https://github.com/milad-alizadeh/argo-universal/pull/2395)

## Implementation order

1. Measure the same one-shot replay in the full Feed on iOS and web. Track an existing glyph relative to its row, track scroll offset separately, and record when a new line or tool card adds height. While following an append-only stream, scroll should progress toward the end without reversing. While reading history, the visible row and its offset should hold during appends. Exercise completion, errors, and history paging as well as steady prose.
2. Keep the answer’s width, leading edge, and settled block identities stable. Invalidate the unfinished suffix when possible. Start with paragraphs and wraps, then test emphasis, links, lists, fences, and tables. Coalesce bursts with a bounded display delay and flush all remaining text at completion. Verify exact final text, Unicode graphemes, line wrapping, selection, and accessibility before adopting a new split strategy. [Codex preview tests](https://github.com/openai/codex/blob/6d9f0199ed0cfdd184754e593e0625917ad0ca28/codex-rs/tui/src/streaming/controller_preview_tests.rs#L379-L481)
3. Prototype opacity on nested native text runs once the geometry is stable. React Native’s iOS text renderer applies run opacity through glyph color alpha. Its layout cache can reuse measurements for runs whose boundaries and metrics stay fixed, although display work still needs profiling. Use one animation clock for active runs, and preserve each run’s original start time through new chunks. Test that a newly visible glyph gets steadily more opaque while older glyphs stay opaque and keep their positions. Include Reduce Motion, larger text, selection, and VoiceOver in the iOS proof. [iOS attributed text](https://github.com/facebook/react-native/blob/5c35c82cf7dd322bf94d47501508c3de975c077b/packages/react-native/ReactCommon/react/renderer/textlayoutmanager/platform/ios/react/renderer/textlayoutmanager/RCTAttributedTextUtils.mm#L166-L209), [text measurement cache](https://github.com/facebook/react-native/blob/5c35c82cf7dd322bf94d47501508c3de975c077b/packages/react-native/ReactCommon/react/renderer/textlayoutmanager/TextMeasureCache.h#L118-L143)
