# Claude and Codex Usage limits

Research date 2026-11-18. The source checks cover the installed Claude ACP 0.108.1 and Codex ACP 2.7.0 releases. The live checks establish what those Agents returned for the accounts used during the investigation.

## Limits depend on the account

| Agent | Limits the provider documents |
| --- | --- |
| Claude | Pro and Max have a five-hour window and an all-model weekly window. Max and Ultra also have a Fable weekly window. Verified Ultra accounts omit the five-hour window. A monthly cap on optional paid usage is separate from the included windows. [Claude plans in Claude Code](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-max-or-ultra-plan), [usage credits](https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans) |
| Codex | OpenAI lists a monthly window for Go, five-hour and weekly windows for Plus and Business Standard, and a weekly window for Pro tiers. Separate model buckets and workspace spend limits can also apply. [Codex reset guide](https://help.openai.com/en/articles/20001498-how-resets-work-in-codex), [Codex plans](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan), [rate card](https://help.openai.com/en/articles/11481834-chatgpt-rate-card) |

Read the windows the Agent actually reports. A missing window could reflect the account, its current activity, or the source's coverage. For example, Claude's five-hour window starts on the first message for accounts with that limit. [Claude Usage limits](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work)

## Claude

Claude ACP passes request-level `rate_limit_event` readings through `usage_update._meta["_claude/rateLimit"]`. On the live account that event showed the all-model weekly window alone. These readings describe the current request and the available unified response headers. The account snapshot can include other meters. [Claude ACP v1 update handling](https://github.com/agentclientprotocol/claude-agent-acp/blob/v0.108.1/src/v1/acp-agent.ts#L7095-L7114), [Agent SDK declarations](https://unpkg.com/@anthropic-ai/claude-agent-sdk@0.3.326/sdk.d.ts)

The adapter's `/usage` command reads a structured SDK snapshot and formats it as Markdown. The renderer includes the five-hour window, the all-model weekly window and every reported model-specific weekly window. It falls back to the older Opus and Sonnet fields when the model-scoped list is empty. The schema accepts optional extra-usage spending data. The formatter prints window, session and behavior data. A proposed ACP method for the structured snapshot closed before merge. [Claude ACP command](https://github.com/agentclientprotocol/claude-agent-acp/blob/v0.108.1/src/v1/acp-agent.ts#L560-L595), [Markdown formatter](https://github.com/agentclientprotocol/claude-agent-acp/blob/v0.108.1/src/usage-markdown.ts#L169-L230), [extension proposal](https://github.com/agentclientprotocol/claude-agent-acp/pull/915)

The installed adapter's `--cli` passthrough returned the structured snapshot from `get_usage` after initialization in stream JSON mode without persisting a Session. Setting `skip_behaviors: true` avoids the local transcript scan. The response contained no five-hour reading and returned both an all-model weekly row and a Fable weekly row. The Fable row's `is_active` flag was false. The SDK defines that flag as the server's choice of headline meter, so clients can still display the row. [Adapter CLI entry](https://github.com/agentclientprotocol/claude-agent-acp/blob/v0.108.1/README.md), [Agent SDK declarations](https://unpkg.com/@anthropic-ai/claude-agent-sdk@0.3.326/sdk.d.ts)

The structured meter rows use a percentage from 0 to 100 and a nullable ISO 8601 reset timestamp. The older named windows also use percentages and ISO timestamps. The live ACP `rate_limit_event` uses a fraction and epoch seconds. The optional monthly extra-usage spend has an enabled flag, amounts in currency minor units, and a nullable utilization percentage. That payload has no reset timestamp. [Agent SDK declarations](https://unpkg.com/@anthropic-ai/claude-agent-sdk@0.3.326/sdk.d.ts), [adapter validation](https://github.com/agentclientprotocol/claude-agent-acp/blob/v0.108.1/src/usage-markdown.ts#L1-L69)

## Codex

Codex ACP stores the native account updates and formats them for `/status`. Its ACP Usage update and v2 quota metadata carry token usage. They do not expose those account windows. The native formatter rounds remaining percentages, formats reset times in the process locale and calls every window of a week or longer weekly. A client cannot recover a monthly window or exact reset timestamp from that text. A proposed ACP update carrying structured account windows remains open. [Codex ACP event handler](https://github.com/agentclientprotocol/codex-acp/blob/v2.7.0/src/CodexEventHandler.ts#L1433-L1448), [status formatter](https://github.com/agentclientprotocol/codex-acp/blob/v2.7.0/src/CodexCommands.ts#L658-L758), [ACP issue](https://github.com/agentclientprotocol/codex-acp/issues/227), [proposed metadata](https://github.com/agentclientprotocol/codex-acp/pull/334)

OpenAI documents `account/rateLimits/read` in the Codex App Server. The multi-bucket view is keyed by the service's limit IDs. The single-bucket view is the compatibility fallback. Each bucket can have primary and secondary windows, with used percentage, nullable duration in minutes, and nullable reset in Unix seconds. Buckets can identify a related model. The optional individual spend limit is distinct from those windows. The installed adapter's `cli app-server --listen stdio://` passthrough returned one weekly primary window and no secondary window on the live account, without opening a Thread. [Codex App Server](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt), [snapshot schema](https://github.com/agentclientprotocol/codex-acp/blob/v2.7.0/src/app-server/v2/RateLimitSnapshot.ts), [CLI entry](https://github.com/agentclientprotocol/codex-acp/blob/v2.7.0/src/index.ts#L30-L39)

## Implications for Argo

Argo can display each reported window, including additional model windows. Keep optional reset timestamps and unreported percentages unknown. The structured reads reuse the installed Agents' sign-in and leave Session execution in ACP. A native read goes beyond the ACP source used for the Composer today.
