# Agent discovery of Argo

Research date: 2026-10-29. Scope: the Agent Client Protocol (ACP) Session interface Argo uses, not a generic model API. Sources below describe upstream protocol or adapter behavior; they do not establish which adapter version is installed on a particular machine.

## Findings

- Argo currently opens Sessions with a checkout path and an empty `mcpServers` array ([source](../../packages/engine/src/sessions/acp/acp-session-opening.ts)). It adds its CLI and a Session token at process launch when Agent access is enabled ([source](../../packages/engine/src/operations/session-launch.ts)); Agent access defaults to enabled ([source](../../packages/engine/src/agent-access/policy.ts)). The existing discovery Skill is installed only by an explicit action ([source](../../packages/engine/src/agent-access/install.ts)).
- Stable ACP v1 documents `cwd` and `mcpServers` for `session/new`, and sends MCP server definitions again when loading a Session ([ACP session setup](https://agentclientprotocol.com/protocol/v1/session-setup)). It does not document a stable client system-prompt field there.
- ACP has an **unstable draft** Session `systemPrompt` field. It requires an Agent to advertise `agentCapabilities.sessionCapabilities.systemPrompt`; clients may then send text in `append` mode. Clients should resend the same instructions on load, resume and fork. An Agent may defer changed instructions until it rebuilds its prompt, such as after compaction ([ACP draft](https://github.com/agentclientprotocol/agent-client-protocol/blob/main/docs/protocol/v1/draft/session-setup.mdx)). This is a protocol draft, not evidence that all Agents or installed releases support it.
- Upstream `codex-acp` main documents that it advertises the draft capability and appends text to Codex developer instructions, preserving base instructions. Changed prompts on existing Sessions may take effect only after compaction. Restart and resume handling require resending the prompt ([adapter documentation](https://github.com/agentclientprotocol/codex-acp/blob/main/readme-dev.md)). The version currently installed from Argo's Registry has not been checked against that upstream main revision.
- `claude-agent-acp` has an adapter-specific `_meta.systemPrompt` mechanism for appending or replacing instructions, documented in its own [changelog](https://github.com/agentclientprotocol/claude-agent-acp/blob/main/CHANGELOG.md), including append support since 0.6.0. Its [merged change for custom session instructions](https://github.com/agentclientprotocol/claude-agent-acp/pull/1177) was released in 0.89.0. Upstream main also processes the draft top-level field and gives it precedence over the metadata extension ([source](https://github.com/agentclientprotocol/claude-agent-acp/blob/main/src/acp-agent.ts)). The exact interface and resume behavior need testing against the installed adapter. Do not assume that Claude's adapter-specific metadata is the same as the newer ACP draft field.
- A separate Pi adapter, `@automatalabs/pi-acp`, documents `_meta.systemPrompt` append and replace ([package documentation](https://www.npmjs.com/package/%40automatalabs/pi-acp)). This does not establish that the particular Pi adapter in Argo's Registry is the same package or supports it. A different [independently maintained Pi adapter](https://github.com/regadas/pi-acp) says it rejects client-mounted MCP. Do not generalize either result to all Pi adapters.
- Versioned source checks below establish Session-instruction support for the Registry's Codex and Claude releases, and its absence from the checked Gemini, OpenCode and Pi ACP Session handlers. No universal cross-Agent prompt mechanism is established by these findings.

## Versioned Session-instruction support check

The [current ACP Registry](https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json), inspected on 2026-10-29, lists the versions below. These are upstream Registry versions, not proof of the version installed in an existing Argo Session. This source inspection confirms the interfaces; no live model run was performed.

| Registry Agent | Version | Client-supplied Session instructions |
| --- | --- | --- |
| Codex ACP | 2.5.0 | Yes: advertises `sessionCapabilities.systemPrompt`; text-only append preserves existing developer instructions. Changed instructions on resume affect retained context at the next compaction. [Tagged documentation](https://github.com/agentclientprotocol/codex-acp/blob/v2.5.0/readme-dev.md#client-system-prompts), [integration tests](https://github.com/agentclientprotocol/codex-acp/blob/v2.5.0/src/__tests__/integration/system-prompts.test.ts). |
| Claude ACP | 0.99.1 | Yes: the draft top-level field supports text append and override. Append keeps the Claude Code preset. Changed instructions on resume may wait until compaction. [Tagged implementation](https://github.com/agentclientprotocol/claude-agent-acp/blob/v0.99.1/src/client-system-prompt.ts). |
| Gemini CLI | 0.66.0 | No Session append interface in the checked ACP implementation: initialization advertises no system-prompt capability and `newSession` takes only `cwd` and `mcpServers`. It has a separate `GEMINI_SYSTEM_MD` process environment setting, but this completely replaces the built-in system prompt; it is not a safe equivalent to append. [ACP dispatcher](https://github.com/google-gemini/gemini-cli/blob/v0.66.0/packages/cli/src/acp/acpRpcDispatcher.ts), [Session manager](https://github.com/google-gemini/gemini-cli/blob/v0.66.0/packages/cli/src/acp/acpSessionManager.ts), [override documentation](https://github.com/google-gemini/gemini-cli/blob/v0.66.0/docs/cli/system-prompt.md). |

| pi ACP (`svkozak/pi-acp`) | 0.0.34 | No Session instruction interface in the checked source. It advertises list/delete capabilities and creates Sessions from `cwd` and stored `mcpServers`. [Version-matching source](https://github.com/svkozak/pi-acp/blob/04d0a15d6bb42bb65cce5c9caedcdcb2cdcb6905/src/acp/agent.ts#L256-L291). |

For context use, a short instruction can point to the existing CLI and defer Operation schemas until a matching discovery call. It is likely smaller in initial context than two fully loaded MCP tool schemas, but that comparison has not been measured. MCP can also defer Operation schemas behind a list/run interface, and some Agents defer tool definitions themselves. Compare complete task traces and model-facing schemas before assigning token savings. Instruction-based CLI use still requires an existing shell tool and permission to reach the local Server.

## Implications and unresolved checks

A short Session instruction can tell an Agent that `argo` is on PATH and to discover Operations with `argo operations <filter> --json`. It can avoid a home-folder Skill where the Agent supports an appropriate channel, but it does not grant shell or network access and is not an authorization control. The Server must continue to enforce Session scope and Operation confirmation. Switch-off semantics must account for existing Sessions and cached or persisted instructions: merely omitting a future instruction does not revoke an existing token or erase prior model context.

An MCP adapter can expose a small discovery and execution surface from the same Operation registry and can be passed at Session opening via ACP. It still requires an MCP server implementation, per-Session authentication, permissions and compatibility tests. ACP's MCP facility is not proof every adapter implements each transport; Pi variants differ. MCP tool exposure and discovery behavior also varies by Agent. A hybrid can use capability-gated prompt append for supported Agents and an independently chosen fallback; test rather than silently assuming support.

Before implementation, check actual Registry IDs and versioned releases, whether initialize capability parsing preserves the draft field, adapter-specific Claude behavior, Gemini/OpenCode/Pi behavior, sandbox and localhost access, Session reopen and compaction, and end-to-end Operation confirmation. This would alter the timing of MCP or Skill delivery recorded in [ADR-0044](../adr/0044-argo-is-driven-through-one-operation-registry-and-the-argo-cli.md); that ADR has not been changed.
