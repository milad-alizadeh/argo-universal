# The Prickles canon is the coding standard

The Prickles canon v2.0, kept verbatim in `docs/agents/prickles/`, is Argo's coding standard. Where it conflicts with `AGENTS.md`, another ADR or a `docs/agents/` doc, the canon wins, including its literal caps: 15-line functions, cyclomatic complexity 3, depth 3, 10 statements, 3 parameters and 150-line files (owner, 2026-10-07). Debt lists and per-occurrence suppressions go; a cap that is wrong changes globally, with the reason written down, as S2 says.

Where the canon cannot apply as written, these are the recorded applications (owner, 2026-10-07):

1. **Tests.** Test files get one documented global cap in the linter config, not a list of exempt files.
2. **XState.** `setup({ types: {} as … })` has no cast-free form in XState v5. One override for `*machine.ts` files covers that cast and the file cap; it is T2's written-down exception.
3. **Outside protocol payloads.** Upstream SDK types own method arguments and responses. SDK readers validate ACP traffic where their public API provides validation. Argo validates App input, database hydration and untyped extensions once at their respective boundaries. Internal functions trust accepted typed values. The Feed validates the Argo row that it assembles, rather than the ACP payload again.

   The public ACP SDK 1.7 validates inbound request and notification payloads and response envelopes. It does not validate response bodies. The owner approved official schema readers for these unchecked bodies on 2026-10-09, under Spec 0009. Argo compiles the SDK's exported `schema/schema.json` definitions with Ajv2020 and validates each used response body once before domain use. These readers retain official response types. Session still calls SDK methods directly. No transport decoder, schema copy, private SDK import or response cast supplies the missing validation.

   Argo reports and counts the rejections that it observes. The SDK owns hidden rejections and diagnostics. Unknown notifications can be silently ignored under its forward-compatible policy. Argo does not intercept global console output or promise a count of every wire rejection. Native protocol readers remain mechanically generated from pinned upstream types until their consumers leave the repository. Handwritten upstream schemas and per-adapter machines remain prohibited.

   Outside data has finite budgets (owner, 2026-10-10, #358). The SDK reads each Agent frame up to 32 MiB; a larger frame fails the connection with the SDK's `MessageTooLargeError` as its reason. Content inside a frame is not cut, except tool output under ADR-0005. Before a Session claims them, at most 64 updates or 256 KB wait, and at most 64 openings run on one connection; past either the opening fails with a named reason. Malformed notifications get one SDK diagnostic and never reach Argo, so Argo does not count them. Rejected response bodies, unknown Session destinations and rejected Feed rows are reported and counted once by Argo.

   The ACP module registers `session/update` as its first user handler and accepts updates synchronously before any await. Completion and closure drain accepted Session and Feed work. Public stream tests cover the registration invariant; it is not a general SDK ordering guarantee.

   Accepted inbound callbacks retain both their completion and the SDK's response write, associated before callback dispatch by the public handler requestId. A private wrapper forwards public typed Stream messages unchanged and observes writable fulfillment/rejection; it neither decodes JSON nor validates or copies response shapes. Session close bounds protocol closure plus this drain together. Owned callback rejection is reported/counted, fences the failed resource, and requires exit proof before ownership release. Observed process exit may settle obsolete write observations without claiming delivery (owner, 2026-10-09, #348). The exact Engine ACP process launcher is an additional allowed child-process import; other Engine production modules remain prohibited.
4. **React components.** The function cap applies to components; long ones split into named subcomponents and hooks.
5. **Unit and integration tests.** Vitest runs a `unit` project under TS7 (no database, network, clock, filesystem or environment) and an `integration` project under TS4, where the composition, database and git tests keep real SQLite and real git. [Testing seams](../agents/testing-seams.md) maps Argo's public surfaces to these layers. The external Agent and Registry fixtures in [ADR-0018](0018-app-e2e-uses-shared-agent-fixtures.md) are a deliberate, bounded exception to TS4's upstream contract-test and recorded-interaction requirement; they do not replace owned dependencies inside the tested system or prove actual upstream compatibility (owner, 2026-10-09).
6. **Gherkin.** Acceptance criteria in spec issues are written as Given/When/Then. End-to-end tests the owner reads use Scenario Outlines.
7. **Pattern names.** PT1 names apply only where the pattern is unmistakable. "Repository" keeps its `GLOSSARY.md` meaning, a git repository.
8. **Server Components.** A8 is met by ADR-0002: the Server owns the data and the logic beside it. The Expo app stays a bundled UI with no React Server Components, which is the canon's native default.

9. **A2 folder mapping.** The tiers map onto screaming feature folders (Spec 0011, owner, 2026-10-10, amending the Spec 0006 mapping that kept the existing folders). The client's features are sessions, composer, feed, requests, agents, settings, connection and frame. Inside a feature, `components/` draws from props only, `screens/` holds thin shells, `hooks/` holds data and behaviour hooks, and `state/` holds machines, contexts, stored preferences and extracted pure rules; each appears only where needed. The Feed adds `view/`, the one client translator from Feed rows to the Feed view, and the Connection adds `trpc/`.

   | Tier | Packages | Inside a package |
   |---|---|---|
   | Local | the apps; each Agent adapter folder | client `features/<feature>/`; Engine `src/<module>/`; Supervisor `supervisor/` |
   | Product | contracts, db, engine, the shared Agent module, git, client | client `lib/product/` and each feature's `index.ts`; an Engine module's `index.ts` |
   | Generic | machine-log, uniwind, `tooling/*` | client `lib/generic/`, with the primitives in `lib/generic/primitives/`; Engine `src/lib/` |

   Git is product because Checkout is a `GLOSSARY.md` term (ADR-0008). Shell and Turn have UI homonyms, so their word matches need a person. `lib/product/` holds product code that two or more features share, including navigation, which sits there to avoid a frame–sessions cycle. `lib/generic/` holds code that would compile after an npm publish and never imports a product word.

   Other features import a feature only through its `index.ts`, which is product tier (owner, 2026-10-10). The allowed feature edges are: sessions uses composer, feed, agents and connection; frame hosts section screens from sessions and settings; data hooks use connection. In the Engine, `rpc/` holds the base procedure and error mapping and sits below the modules, and each router takes its own dependencies. oxlint keeps `rpc/` free of module imports and keeps every module off `engine/`, so the Engine composition has no import cycle.

   The Engine's source root names its modules (Spec 0011 #451; owner approval pending in the pull request): `engine`, `rpc`, `sessions`, `feed`, `acp`, `agents`, `blob`, `projects`, `system`, `storage` and `lib`, beside `server-runtime`. `acp` is the ACP transport and its resources. `agents` is the Agent catalog, configuration and launches, with the Registry reader in `agents/registry/`. The two ACP translators are `feed/acp/` and `sessions/acp/`, and the Session read models are `sessions/list/`. The machine that holds the open Sessions is `openSessionsMachine`. `acp` runs the custom Agent check's ACP initialize handshake; `agents` owns the launch types and receives the check as a port, so `agents` never imports `acp`, and `acp` imports only those types from `agents`. oxlint enforces both directions.

   The accepted exceptions are `millisecondsPerSecond` defined once per package, and the Composer importing the Plan proposal card from the requests feature for its card swap (Spec 0006, Owner #17).

   oxlint enforces the import direction with `no-restricted-imports` blocks in `tooling/oxlint/argo.json`; add a block when a tier folder is added. Spec 0011 moves the folders and their blocks ticket by ticket, so CI stays green. When to hoist and whether a name belongs to the product stay with code review, as A2 and TA1 leave them.

10. **Thin Session handlers.** A5 permits the Session tRPC procedure to resolve its actor, apply the current admission checks, send one validated event and return the existing acknowledgement (Spec 0008, owner, 2026-10-08). This routing work stays beside the Session domain. Substantive rules, persistence and native lifecycle belong to domain operations and machines; there is no mandatory forwarding service or actor request/reply protocol.

11. **Router type delivery.** The Engine package (`@repo/engine`) owns the one operational tRPC initialization in `rpc/`, the root router and the domain routers; each domain router closes over the dependencies it names, so a call carries no shared context (Spec 0011 #450; owner approval pending in the pull request). The deployable Server (`apps/server`, `@repo/server`) owns the Supervisor and process startup, exports no library face, and depends on Engine. The App infers procedure inputs and outputs through `import type { AppRouter } from '@repo/engine/router'`, derived from that real router (Spec 0008, owner, 2026-10-08). This narrow type dependency is the application of A2/A3: oxlint rejects Engine runtime imports, unrelated Engine types and every deployable Server import in App production code. Reusable packages never depend on the deployable Server (owner, 2026-10-09). Canonical schemas stay in Contracts. Tests may load the real router. Shared App mocks live in `mocks/app` and export through the browser-safe `@repo/mocks/app` entry. The Server and desktop share the narrow Node-only `@repo/engine/server-runtime` entry (Spec 0009 #347, owner, 2026-10-09); App E2E reads and writes `server.json` through it too (Spec 0011 #448, owner, 2026-10-10). The obsolete API package is removed. App typechecks and web/native builds prove the type graph and bundle boundary.

12. **Registry metadata.** The official ACP Registry JSON schemas own the catalog shape. Contracts keeps the original schemas and publisher from upstream commit `33a1a101ef68ab20a97624ac89d4b977eeac0daf`. The publisher emits an empty `extensions` placeholder that its schema omits. Generation mechanically adds only that literal empty array, without executing the publisher, after checking its SHA-256 `ac3e7008ccccdb42852bc9e3780d46078cfaf9e0f92c39d59427d3294eb12207`. Nonempty or differently typed extensions remain unsupported and rejected. All other upstream schema rules stay intact, including permitted Agent metadata. Installed `json-schema-to-typescript` 16.0.0 derives the types. `pnpm --filter @repo/contracts generate:registry` regenerates only the published registry schema and these types. The Engine decodes and validates each response once at registry intake. SQLite row hydration validates the schema-derived row envelope and official Agent metadata once per read. Catalog search, recipe selection, and tRPC output use those accepted values without another parse. Each catalog query reports and counts its own hydration rejections; upstream sync rejection totals remain durable in SQLite. Duplicate registry identities are reported and counted at registry intake because one durable row must own each registry identity. Rejected input is logged and counted (Spec 0009 #361, owner, 2026-10-09).

Enforcement lands through a spec issue, folder by folder, so CI stays green.

## Considered Options

- Argo's own rules win where they conflict (the first `AGENTS.md` pointer). Rejected: the owner wants the canon applied as written.
- Adapted rule docs (`docs/agents/code-shape.md`, `docs/agents/testing.md`). Removed: they restated the canon in other words and disagreed with it.
