# The Prickles canon is the coding standard

The Prickles canon v2.0, kept verbatim in `docs/agents/prickles/`, is Argo's coding standard. Where it conflicts with `AGENTS.md`, another ADR or a `docs/agents/` doc, the canon wins, including its literal caps: 15-line functions, cyclomatic complexity 3, depth 3, 10 statements, 3 parameters and 150-line files (owner, 2026-10-07). Debt lists and per-occurrence suppressions go; a cap that is wrong changes globally, with the reason written down, as S2 says.

Where the canon cannot apply as written, these are the recorded applications (owner, 2026-10-07):

1. **Tests.** Test files get one documented global cap in the linter config, not a list of exempt files.
2. **XState.** `setup({ types: {} as … })` has no cast-free form in XState v5. An override for `*machine.ts` files permits that cast. Machine files have no line cap (owner, 2026-10-29). A cap would force statecharts apart when their lifecycle needs more states and transitions.

   Keep each machine's statechart together: states, transitions, guard references and timeout ordering stay readable in one file (owner, 2026-10-13). Extract invoked operations, action implementations and input construction where they improve clarity. Introduce child actors when they own a distinct lifecycle or responsibility. Do not split a statechart across files solely to satisfy lint limits.

3. **Outside protocol payloads.** Upstream SDK types own method arguments and responses. SDK readers validate ACP traffic where their public API provides validation. Argo validates App input, database hydration and untyped extensions once, each at its boundary. Internal functions trust accepted typed values. The Feed validates the Argo row it assembles, not the ACP payload again.

   The public ACP SDK 1.7 validates inbound request and notification payloads and response envelopes, but not response bodies. The owner approved official schema readers for these unchecked bodies on 2026-10-09, under Spec 0009. Argo compiles the SDK's exported `schema/schema.json` definitions with Ajv2020 and validates each used response body once before domain use. These readers keep official response types, and Session still calls SDK methods directly. No transport decoder, schema copy, private SDK import or response cast supplies the missing validation.

   Argo reports and counts the rejections it observes. The SDK owns hidden rejections and diagnostics. Unknown notifications can be silently ignored under its forward-compatible policy. Argo does not intercept global console output or promise a count of every wire rejection. Spec 0009 #359 deletes native protocol readers and their generators. Handwritten upstream schemas and per-Agent machines stay prohibited, apart from the draft subagent reader below.

   One recorded exception reads GitHub's Release API, which has no installed SDK types: `agents/launch/github-digest.ts` parses only an asset's `name` and `digest`, once at that boundary, to find a Registry binary's checksum (Spec 0014 #718, owner, 2026-10-16).

   A second recorded exception reads the draft subagent notifications (owner, 2026-10-27). Agents send `subagent_spawned` and `subagent_state_update` where the standard schema has `subagent_update`, and the SDK reads neither. `agents/acp/connection/draft-subagent-updates.ts` holds one handwritten reader for those two: it translates them into the standard update on the input stream, and rejects, reports and counts any draft it does not recognise ([ADR-0015](0015-one-agent-machine-runs-every-adapter.md)). It is deleted once the Agents Argo supports send the standard update.

   Outside data has finite budgets (owner, 2026-10-10, #358). The SDK reads each Agent frame up to 32 MiB; a larger frame fails the connection with the SDK's `MessageTooLargeError` as its reason. Content inside a frame is not cut, except tool output under ADR-0005. Spec #717 removed the opening and early-update limits (owner, 2026-10-15). Malformed notifications get one SDK diagnostic and never reach Argo, so Argo does not count them. Rejected response bodies and rejected Feed rows are reported and counted once by Argo; an update for an unknown Agent session is logged at warn and dropped, so `agents/acp/connection/connection.ts` alone may call `console.warn`.

   The ACP connection registers a Session's id as soon as its `session/new` or `session/resume` response is read, before the next inbound message is handled, as Zed's `registration_finished` barrier does (#717). Completion and closure drain accepted Session and Feed work. Public stream tests cover this registration invariant, which is not a general SDK ordering guarantee. The connection stays in one file, `agents/acp/connection/connection.ts`, which the owner exempted from the file cap on 2026-10-15.


   Session close is bounded; a close that times out or fails releases the Session (#717). The exact Engine ACP process launcher and the login-shell environment reader in `agents/launch/shell-env.ts` are also allowed child-process imports. Spec 0003 #71 permits `engine/caffeinate.ts` to launch `caffeinate -i -w <Engine pid>` while any Turn runs. Spec 0016 #735 permits `plugins/keychain.ts` to run the macOS `security` CLI for Plugin secrets. Other Engine production modules cannot import child-process APIs. Spec 0014 #722 permits `agents/launch/processes/process.ts` to run download and npm tools in the Engine process group. `packages/process` is the generic home for child-process lifecycle, from spawn to process-group release, which desktop, the Supervisor and App E2E share.
4. **React components.** The function cap applies to components; long ones split into named subcomponents and hooks.
5. **Unit and integration tests.** Vitest runs a `unit` project under TS7 (no database, network, clock, filesystem or environment) and an `integration` project under TS4, where the composition, database and git tests keep real SQLite and real git. The external Agent and Registry fixtures in [ADR-0018](0018-app-e2e-uses-shared-agent-fixtures.md) are a deliberate, bounded exception to TS4's upstream contract-test and recorded-interaction requirement; they do not replace owned dependencies inside the tested system or prove actual upstream compatibility (owner, 2026-10-09).
6. **Gherkin.** Acceptance criteria in spec issues are written as Given/When/Then. End-to-end tests the owner reads use Scenario Outlines.
7. **Pattern names.** PT1 names apply only where the pattern is unmistakable. "Repository" keeps its `GLOSSARY.md` meaning, a git repository.
8. **Server Components.** ADR-0002 meets A8: the Server owns the data and the logic beside it. The Expo app stays a bundled UI with no React Server Components, the canon's native default.
9. **A2 folder mapping.** The tiers map onto screaming feature folders (Spec 0011, owner, 2026-10-10, amending the Spec 0006 mapping that kept the existing folders). The client's features are sessions, composer, feed, requests, agents, settings, connection and frame. Inside a feature, `components/` draws from props only, `screens/` holds thin shells, `hooks/` holds data and behaviour hooks, `utils/` holds pure functions, `stores/` holds client contexts and stored preferences, `api/` holds Server calls, and `types/` holds shared types. Each folder appears only where needed (Spec 0014 #710). The Feed adds `view/`, the one client translator from Feed rows to the Feed view, and the Connection keeps its tRPC client in `api/trpc/`.

   | Tier | Packages | Inside a package |
   |---|---|---|
   | Local | the apps; the Agents domain | client `features/<feature>/`; Engine `src/<module>/`; Supervisor `supervisor/` |
   | Product | contracts, db, engine, the shared Agent module, git, client | client `lib/product/` and each feature's `index.ts`; an Engine module's `index.ts` |
   | Generic | machine-log, process, uniwind, `tooling/*` | `@repo/kit`, with the primitives in `packages/kit/src/primitives/`; Engine `src/lib/` |

   Git is product because Checkout is a `GLOSSARY.md` term (ADR-0008). Shell and Turn have UI homonyms, so their word matches need a person. `lib/product/` holds product code that two or more features share, including navigation, which sits there to avoid a frame–sessions cycle. `@repo/kit` holds code that would compile after an npm publish and imports no product word.

   Other features import a feature only through its `index.ts`, which is product tier (owner, 2026-10-10). The allowed feature edges are: sessions uses composer, feed, agents, connection and requests; frame hosts section screens from sessions and settings; data hooks use connection. The owner approved sessions using requests for live Elicitation presentation on 2026-10-13 (#430). In the Engine, `rpc/` holds the base procedure and error mapping and sits below the modules, and each router takes its own dependencies. oxlint keeps `rpc/` free of module imports and keeps every module off `engine/`, so the Engine composition has no import cycle.

   The Engine's source root names its modules (Spec 0011 #451; ACP-only ownership completed under Spec 0009 #359, owner, 2026-10-13): `engine`, `rpc`, `sessions`, `feed`, `agents`, `blob`, `projects`, `system`, `storage` and `lib`, beside `server-runtime`. `agents` owns the Registry cache, saved Agent choices, authentication and lazy launch. Its `agents/acp/` group owns ACP transport and resources after Spec 0009 #359 (owner, 2026-10-13). The Registry reader stays in `agents/registry/`. The Feed and Session translators stay in `feed/acp/` and `sessions/acp/`. Other domains consume the Agents public interface; ACP resources never import Session or Feed code. The machine that holds open Sessions is `openSessionsMachine`.

   The accepted exception is `millisecondsPerSecond` defined once per package.

   oxlint enforces the import direction with `no-restricted-imports` blocks in `tooling/oxlint/argo.json`; add a block when a tier folder is added. Spec 0011 moves the folders and their blocks ticket by ticket, so CI stays green. When to hoist, and whether a name belongs to the product, stay with code review, as A2 and TA1 leave them.

10. **Thin Session handlers.** A5 permits the Session tRPC procedure to resolve its actor, apply the current admission checks, send one validated event and return the existing acknowledgement (Spec 0008, owner, 2026-10-08). This routing stays beside the Session domain; substantive rules, persistence and ACP Session lifecycle belong to domain operations and machines, with no mandatory forwarding service or actor request/reply protocol.

11. **Router type delivery.** The Engine package (`@repo/engine`) owns the one operational tRPC initialization in `rpc/`, the root router and the domain routers; each domain router closes over the dependencies it names, so a call carries no shared context (Spec 0011 #450; ACP-only composition completed under Spec 0009 #359, owner, 2026-10-13). The deployable Server (`apps/server`, `@repo/server`) owns the Supervisor and process startup, exports no library face, and depends on Engine. The App infers procedure inputs and outputs through `import type { AppRouter } from '@repo/engine/router'`, derived from that real router (Spec 0008, owner, 2026-10-08). This narrow type dependency is the application of A2/A3: oxlint rejects Engine runtime imports, unrelated Engine types and every deployable Server import in App production code. Reusable packages never depend on the deployable Server (owner, 2026-10-09). Canonical schemas stay in Contracts. Tests may load the real router. Shared App mocks live in `mocks/app` and export through the browser-safe `@repo/mocks/app` entry. The Server and desktop share the narrow Node-only `@repo/engine/server-runtime` entry (Spec 0009 #347, owner, 2026-10-09); App E2E reads and writes `server.json` through it too (Spec 0011 #448, owner, 2026-10-10). The obsolete API package is removed. App typechecks and web/native builds prove the type graph and bundle boundary.

12. **Registry metadata.** The official ACP Registry JSON schemas own the catalog shape. Contracts keeps the original schemas and publisher from upstream commit `33a1a101ef68ab20a97624ac89d4b977eeac0daf`. The publisher emits an empty `extensions` placeholder that its schema omits. Generation mechanically adds only that literal empty array, without executing the publisher, after checking its SHA-256 `ac3e7008ccccdb42852bc9e3780d46078cfaf9e0f92c39d59427d3294eb12207`. Nonempty or differently typed extensions remain unsupported and rejected; all other upstream schema rules, including permitted Agent metadata, stay intact. Installed `json-schema-to-typescript` 16.0.0 derives the types. `pnpm --filter @repo/contracts generate:registry` regenerates only the published registry schema and these types. The Engine decodes and validates each response once at registry intake. Registry cache reads validate the schema-derived row envelope and official Registry metadata. Launch selection and tRPC output use those accepted values. Duplicate Registry identities are rejected at intake. Rejected input is logged and counted (Spec 0009 #361, owner, 2026-10-09).

   Spec 0014 #722 removes the old catalog path. Registry cache intake logs rejected values without saving rejection totals (owner, 2026-10-16).

13. **Kit-styling allowlist.** The shrinking allowlist in `tooling/oxlint/kit-styling-allowlist.json` is an accepted exception to "debt lists go" (owner, 2026-10-14, Spec 0015 #724). It names the files that still pass `className`, `style` or a `*ClassName` slot to kit components, which [ADR-0020](0020-argo-owns-its-primitives.md) bans outside `@repo/kit`. `tools/check-rule-allowlists.mts` keeps it honest: once the list is on main it only shrinks, and a file with no findings must leave it.

Enforcement lands through a spec issue, folder by folder, so CI stays green.

## Considered Options

- Argo's own rules win where they conflict (the first `AGENTS.md` pointer). Rejected: the owner wants the canon applied as written.
- Adapted rule docs (`docs/agents/code-shape.md`, `docs/agents/testing.md`). Removed: they restated the canon in other words and disagreed with it.
