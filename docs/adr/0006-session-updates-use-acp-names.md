# Session uses the ACP SDK, and Feed rows keep product shapes

ACP (Agent Client Protocol) is the standard vocabulary for coding agents. Each Session update carries ACP's `sessionUpdate` discriminator and ACP field names. We take the names from ACP v2 where v2 describes whole items (`user_message`, `agent_message`, `agent_thought`, `tool_call_update`, `plan_update`), because each stored Session update is a whole item. ACP's `state_update` values become the `state` of the Session snapshot, not a Session update. We take the rest from ACP v1, which is the stable version. Fields that ACP lacks go in `_meta.argo`, which is ACP's extension slot. Session updates that ACP lacks get ACP-style names, such as `task_update`.

Spec 0009 replaces the Argo-owned adapter method/event contract with the public ACP SDK (owner, 2026-10-09). Session receives the official SDK role, readiness and protocol identity in one owned lease and calls ordinary methods directly. Engine's private resource seam owns only startup, identity routing and teardown. New identities come from the validated result; load/resume retain their explicit requested identity. Reservations own bounded early updates and route only proven matches. Questions never select a new opening by guess or broadcast.

Feed privately assembles official SDK message chunks, tool changes and Plans into whole product rows. Durable row identity is tagged by actual ACP Session and entity kind; an explicit upstream message ID stays stable across Turns, while an unaddressed message gets a local Feed identity. Supported content and entity metadata lives in `_meta.acp`, separate from product fields in `_meta.argo`. Unselected chunk-only opaque metadata is omitted. Notices and Compaction retain explicit future severity/status values with an unsupported diagnostic. Unsupported media remains a visible kind/reason placeholder with an inert safe reference; Blob materialization remains a later content gate. Empty ACP creation is readable and stores no Turn; during migration, prompted native consumers remain until their dependent tickets replace them. SDK validation owns covered traffic; official schema readers validate unchecked response bodies once under ADR-0016. Unsupported capabilities retain honest outcomes. Spec 0009 #351 normalizes official Session configuration into the existing App envelope without repeating SDK validation; only untyped Argo metadata is decoded, reported and counted at that boundary. Outgoing prompt preparation preserves supported text, Blob image bytes, embedded text context, resource references and opaque ACP metadata. Unsupported input rejects local submission before prompt dispatch. New Session selects Project, Checkout and catalog Agent metadata, opens the real empty Session, then displays negotiated configuration before its first prompt (owner, 2026-10-09).

Spec 0009 #357 keeps the existing context indicator; the owner excludes a usage dashboard and token breakdowns (2026-10-12). Session retains validated ACP context updates and prompt-response counters without inventing absent detail. Missing optional counters remain unavailable; explicit zeroes remain zero. Turn storage qualifies counters with their verified scope; older rows retain their existing shape.

The Agents module owns usage-scope knowledge; the Session ACP translator applies it without copying upstream payload schemas. [Claude ACP 0.88.0](https://github.com/agentclientprotocol/claude-agent-acp/blob/d43fec3fa3118e88ff8a8ed99b85d2a5f444e538/src/acp-agent.ts) accumulates prompt usage within the active Turn and omits thought-token detail. [Codex ACP 2.1.1](https://github.com/agentclientprotocol/codex-acp/blob/68d7d2d5ddfc0ed5746f9f6130892dda685e65dd/src/CodexAcpServer.ts) returns the latest model-call sample, which Argo stores with model-call scope. Its [context update](https://github.com/agentclientprotocol/codex-acp/blob/68d7d2d5ddfc0ed5746f9f6130892dda685e65dd/src/CodexEventHandler.ts) uses that sample as a proxy. Argo retains this proxy but excludes it from the context indicator; it cannot establish exact tokens left. Other unverified prompt totals retain Agent-reported scope, and no model-call samples are accumulated or labelled as whole-Turn totals.

Opening updates remain unverified until the lease supplies the Agent identity. The App excludes unverified context and unknown capacity from the existing indicator. Measured context continues through the shared ContextWindow drawing for both Agent identities. No native side channel or reconstructed accounting supplies missing values.

The glossary follows ACP too: Agent (not Harness), Turn, Stop reason, Elicitation. ACP calls the program that drives an Agent the Client. In Argo that is the Server. Argo avoids the word client, because an App connects to the Server too.
