# Session uses the ACP SDK, and Feed rows keep product shapes

ACP (Agent Client Protocol) is the standard vocabulary for coding agents. Each Session update carries ACP's `sessionUpdate` discriminator and ACP field names. We take the names from ACP v2 where v2 describes whole items (`user_message`, `agent_message`, `agent_thought`, `tool_call_update`, `plan_update`), because each stored Session update is a whole item. ACP's `state_update` values become the `state` of the Session snapshot, not a Session update. We take the rest from ACP v1, which is the stable version. Fields that ACP lacks go in `_meta.argo`, which is ACP's extension slot. Session updates that ACP lacks get ACP-style names, such as `task_update`.

Spec 0009 replaces the Argo-owned adapter method/event contract with the public ACP SDK (owner, 2026-10-09). Session receives the official SDK role, readiness and protocol identity in one owned lease and calls ordinary methods directly. Engine's private resource seam owns only startup, identity routing and teardown. New identities come from the validated result; load/resume retain their explicit requested identity. Reservations own bounded early updates and route only proven matches. Questions never select a new opening by guess or broadcast.

Feed privately assembles official SDK message chunks, tool changes and Plans into whole product rows. Durable row identity is tagged by actual ACP Session and entity kind; an explicit upstream message ID stays stable across Turns, while an unaddressed message gets a local Feed identity. Supported content and entity metadata lives in `_meta.acp`, separate from product fields in `_meta.argo`. Unselected chunk-only opaque metadata is omitted. Notices and Compaction retain explicit future severity/status values with an unsupported diagnostic. Unsupported media remains a visible kind/reason placeholder with an inert safe reference; Blob materialization remains a later content gate. Empty ACP creation is readable and stores no Turn; during migration, prompted native consumers remain until their dependent tickets replace them. SDK validation owns covered traffic; official schema readers validate unchecked response bodies once under ADR-0016. Unsupported capabilities retain honest outcomes.

The glossary follows ACP too: Agent (not Harness), Turn, Stop reason, Elicitation. ACP calls the program that drives an Agent the Client. In Argo that is the Server. Argo avoids the word client, because an App connects to the Server too.
