# The Workbench summarises a Session's sections and the Stage shows them in full

Argo has drawn a column beside the Feed since the first desktop designs, and the owner moved pull requests, checks and file changes into it on 2026-10-20: "the PRs and file changes are going into workbench". Neither the Workbench nor the Stage is written down anywhere. No ADR names them, `GLOSSARY.md` defines neither, and the code still calls both of them the inspector, so [ADR-0035](0035-plugins-add-to-named-slots-and-never-edit-core-screens.md) named a Plugin's Slot there the "inspector tab" before this ADR gave it the Workbench's name. This ADR names the two surfaces, says what each owns, and records the rule the owner set for phones. The rename in code is work, not a decision this ADR makes.

## Decision

- **The Workbench is the desktop and web column beside a Session's Feed,** 312 wide, flush to the window edge, toggled from the Session header. The Feed keeps its 800 cap beside it. There is one Workbench per Session; it is not a second sidebar, and the rail is still where sections live.
- **Nothing the Workbench owns is drawn in a header.** Pull requests, checks, Changes counts and file changes are the Workbench's, on every platform. A Session header carries identity and state only: title, status, the running Turn, the Workbench toggle and "…". A header is a fixed width and a Session's Changes are an unbounded list, so the two never fit.
- **The Workbench holds section cards, and it is an overview of what is happening in the Session.** Argo's cards are Changes, Agents and Shells; the Agents card counts the Agents the Session started, not the Installed Agents the Agents page lists. A card is drawn only when the Session has something for it, so a Session with no Agents has no Agents card, as its header has no Agents button.
- **A card is a summary and nothing else.** The Changes card shows a diff total, the Agents card a count and the role avatars, the Shells card a count. A card never holds its section's items and never reveals them through a disclosure or an expander: the list belongs to the Stage. Cards are kit components, and the lists their Stage tabs draw are `List` and `ListItem` ([ADR-0032](0032-one-list-and-one-list-item-drawn-by-argo-everywhere.md)).
- **A Change is what the Changes card counts and its Stage tab lists.** One line of work, named by its branch, at one of five stages: Working, Branch, Open, Merged or Closed. A Session can have several Changes at once, each at its own stage, so no design may assume one pull request.
- **Plugins add their own cards through a named Slot,** under [ADR-0035](0035-plugins-add-to-named-slots-and-never-edit-core-screens.md) unchanged: the Plugin draws inside its card, Argo decides where the card goes, in what order and how much fits, and a Plugin never moves, hides or restyles Argo's cards or another Plugin's. This Slot is the one ADR-0035 declares for a Plugin page beside the Feed, now under the Workbench's name. A Plugin's `header` action may open its card, as ADR-0035 says.
- **Pressing a Workbench card opens that card's full view in the Stage, as a Stage tab.** The Workbench stays. The Stage is a surface, not a section: it is always reached from a card, never from the rail.
- **A Stage tab is a full view, and it holds a list.** The Agents tab lists the Agents the Session started, grouped and counted by state; the Changes and Shells tabs list theirs the same way. Pressing a row opens that item's detail in the same tab — a Change's diff, an Agent's Feed, a Shell's output — and Back returns to the list. A Stage tab therefore has at least two levels, and a Plugin's tab is whatever the Plugin draws.
- **Phones reach the same content, and the design says how.** Every Workbench card, Plugin cards included, and every Stage tab is reachable on compact widths, where there is no column. The presentation is being settled in Paper and is not fixed here; what is fixed is that nothing is dropped on phones and no card is desktop-only.
- **Each card and each Stage tab get a Paper design before code,** as every new visible state does and as ADR-0035 requires of each Slot.

## Considered options

- **Keep pull requests and checks in the Session header,** as the meta line and a Merge button did until 2026-10-20. Rejected by the owner: a header cannot hold several Changes, and a "+N" dropdown over an unbounded list is the variable-width problem again.
- **Give Changes its own rail section.** Rejected: there is one sidebar and the rail is for Plugin sections (owner, 2026-10-19). Changes belong to a Session, so they belong beside its Feed.
- **Let Plugins place their cards themselves, or reorder Argo's.** Rejected by ADR-0035, for the reasons it gives.
- **Let a Workbench card hold its section's list, and give the Stage one item.** Rejected by the owner: the Workbench is an overview of what is happening in the Session, and 312 of column cannot carry three unbounded lists. A card that lists its items either grows without limit or hides most of them behind a fold, and the Stage is then too thin to be worth a tab.
- **Make the Stage a third column.** Rejected: at 312 plus 800 plus a Stage the Feed loses its width, and a Change's diff needs more room than any column leaves. The Stage covers or replaces, and the Workbench stays.
- **Settle the phone presentation here,** as a sheet or as a drill-in. Left to the design: the compact layout for the cards and the Stage is open in Paper, and an ADR guessing at it would be a decision nobody made.
