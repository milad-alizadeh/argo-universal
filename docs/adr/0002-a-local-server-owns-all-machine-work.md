# A local Server owns all machine work, and Apps connect to it directly

The phone, the web app, and the desktop app must have the same abilities. So the local Server owns Sessions, Agents, git, worktrees, and storage. Its deployable Supervisor and process startup live in `apps/server`; the reusable Engine implementation and domain work live in `packages/engine` (owner, 2026-10-09). Electron never does this work in its main process.

Every App connects to the Server over one WebSocket that carries every tRPC call (`wsLink`, `ws` with `applyWSSHandler`, Zod, no superjson). The one exception is a file upload: tRPC accepts a file only over HTTP, so a client's `splitLink` sends a call whose input is a file through `httpLink`, to the same router served by tRPC's `createHTTPHandler` on the same `node:http` server. A one-shot upload has no reconnect path. Plain HTTP serves only `GET /blobs/:id`, because an image needs a URL that returns its bytes. There is no HTTP framework (owner, 2026-10-03; this replaces Hono). The Electron renderer connects in the same way as the phone. There is no tRPC over Electron IPC. The preload script gives the renderer only the Server address and window controls.

The Server owns the only database: SQLite at `~/.argo/argo.db`, through Drizzle on `node:sqlite`. Apps keep no local database. The TanStack Query cache is enough. This follows Argo ADR-0043, where SQLite owns per-machine state.

The Engine invokes one generic sync supervisor beside the Session Registry and the shared database Writer. HTTP context creation does not start or stop it. Startup repairs unfinished SQL sync requests and prepares saved search data before accepting App calls, but does not fetch the catalog. The App requests sync on an Agents page visit or explicit Refresh. Each request first commits its own pending SQL row through the Writer. The supervisor reacts to that committed intent and coalesces concurrent requests into one finite catalog worker. A replacement and every joined request's completion commit in the same Writer transaction. Late joins copy the completed SQL outcome. Queries, subscriptions, and mutation completion read SQLite; Writer notifications only wake those readers. Search uses the existing Agents rows locally and treats search text as a literal substring (Spec 0009 #361 review amendment, owner, 2026-10-09).

Catalog sync owns registry identity, accepted metadata, presence, search text, and sync time. Removed entries stay as absent rows with their local identity and last accepted metadata. Offline, malformed, or failed writes preserve committed catalog rows and expose durable error outcomes. A rejected catalog job is removed from the Writer queue before its receipt rejects, so a later Session retry cannot silently commit a rejected catalog replacement. Session and Feed retry behavior stays intact. If recording a sync failure also fails, its request remains pending; the next explicit Refresh must commit its interruption before starting a new fetch.

Disconnecting an App detaches its observer without cancelling admitted work. Engine shutdown closes command admission, cancels a pending Registry fetch, waits for admitted worker and join receipts, and always queues a final interruption write after admitted requests. That final shutdown write immediately attempts an existing retrying prefix and its interruption together, using the same ordered final-attempt behavior as Writer drain. Ordinary writes keep their retry cadence. It drains the shared Writer before closing SQLite. If the interruption cannot commit, the Engine logs the failure and retains its storage cleanup state instead of claiming a safe close. Shutdown remains pending; the Server process owner applies its existing 25-second SIGTERM-to-SIGKILL deadline. SQLite rolls back any uncommitted transaction, and pending sync requests are interrupted during the next startup. Startup seed and crash recovery run before the live Writer; live catalog, Session, Feed, and Blob metadata writes all use that one Writer. Blob bytes remain files, and metadata is acknowledged only after its Writer receipt. Browsing does not launch Agents or create Sessions.

`agents` is the durable read-model foundation for catalog and local Agent facts. Registration (#362) extends these same rows with local definitions, non-secret configuration and installation observations; those later behaviors are not implemented by catalog sync. Credentials stay upstream, and a stored installation observation is not permanent readiness. The direct Agents creation migration uses the existing database connection and migration transaction. Existing main migrations and Session/Turn/Feed history stay intact.

For now the Server binds to `127.0.0.1` only and has no authentication. It checks `Host` on every request, and `Origin` on the WebSocket and on tRPC over HTTP, so a website open in a browser on the same machine cannot call it (owner, 2026-10-03). Pairing a real phone and authentication come later, with their own ADR.

## Considered Options

- Run the Server inside the Electron main process. Rejected: the phone cannot use it when desktop is closed, and Argo's current tRPC-over-IPC bridge is the code we want to remove.
- A custom JSON protocol over WebSocket, as Paseo does. Rejected: tRPC gives typed procedures and TanStack Query hooks for free.
- HTTP for queries and WebSocket only for subscriptions. Rejected: two transports means two reconnect paths.
- Uploads as base64 over the WebSocket. Rejected: a third larger, and a big image holds up the socket that streams the Feed.
- Hono for the plain HTTP routes. Replaced on 2026-10-03: once `/health` became a tRPC query, one blob route did not need a framework.
