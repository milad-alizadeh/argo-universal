# Plugin pages are a loader and a pure render, and the App's React owns everything that moves

This amends [ADR-0025](0025-plugins-run-on-the-server-and-draw-argo-components.md), [ADR-0027](0027-plugins-act-through-one-api-hook-core-and-replace-named-components.md), [ADR-0031](0031-the-plugin-wire-sends-keyed-patches-and-kit-components-turn-stable-in-use.md) and [ADR-0037](0037-plugins-declare-the-data-they-need.md), and builds on [ADR-0044](0044-argo-is-driven-through-one-operation-registry-and-the-argo-cli.md) (owner, 2026-11-03). ADR-0025 copied Raycast: a Plugin's React runs in its worker behind a custom reconciler, and the App draws a mirror of that tree from snapshots and keyed patches. Raycast's worker and its host share one Mac and talk over a pipe. Argo's App is across Wi-Fi or a relay from the Server, so every Plugin screen exists twice with a network between the copies, and every tap, toggle and "load more" crosses it to change state on the Server. Spec 0026's steps 2 to 4 (#1934, #1935, #1936) are spent keeping the two copies in step: which views stay open, which trees the App keeps, which rows keep their identity. VS Code's tree views, Slack's Block Kit and Adaptive Cards keep hooks out of the plugin entirely, and Remix and React Router split a route into a `loader` that reads and an `action` that writes. We copy that split and keep Argo's kit and JSX.

## Decision

- **No React on the Server.** A Plugin page or Slot is two plain functions: a loader, which reads and answers the page's data, and a render, which turns that data into a Plugin tree. The render is pure: no hooks, no state, no fetching. Function components without hooks still compose. JSX compiles to plain objects, so the worker needs no reconciler, holds nothing mounted between calls, and keeps no view per Connection. A Plugin may still keep its own data between calls, as any module may, such as the cursors of pages it has read; that memory is the Plugin's, not a mirror of the App.
- **A tree is a value, fetched like any other.** The App asks for a page by its Page address: its Plugin, Page path, Page state and context, and the Server answers with the tree, validated against the kit schemas in Contracts as ADR-0031 already does. The App keeps each answer in TanStack Query, so a page seen before draws at once, unchanged rows keep their identity through structural sharing, and an App offline draws its last answer. Snapshots, keyed patches, revisions and per-Connection views go, except for live pages below. The App names the hash of the tree it keeps for the address, so the Server answers `unchanged` when nothing differs and only the new rows when a load more grows one List; anything else is the whole tree.
- **Every write is an Operation.** A tappable prop names either a navigation, a change to Page state, or an Operation with its arguments, as a value; no function crosses the wire, and there is no Component event lookup by node key. The Operation is the same one ADR-0044 registers, so a person's tap, an Agent's `argo run` and a Hook reach one handler. Each is declared in the manifest with its params schema, which the Server checks the App's arguments against. A Component event that reports a payload, as a Table's sort or a List's move, says in the value where each field of it goes: a key of a Page state change or an argument of an Operation call. The App fills the fields in when the event fires and acts with no round trip to the Plugin; Page state still holds scalars only, so an object payload lands in flat keys, and the Server checks the filled-in arguments as it checks any run. A tap's caller is the person at that App, with the page's Project and Session as its scope. A person tapping a Plugin's own button has already chosen; a `confirm` tier still asks an Agent, and a Plugin that wants a person to confirm draws its own Dialog.
- **The loader answers what is stale.** A loader reads through Argo's Queries (ADR-0037), so Argo knows what each Page address read. A Plugin's Operation runs, and the Plugin's own `argo.changed()` from any of its code, are writes: they make every Query the Plugin keeps due and mark all of its addresses stale, and the mark names no address. A Query answer that changes with no write, as when a background pass reads it again, marks only the addresses whose last draw read it. The Server pushes each mark to every connected App, and each App refetches the marked pages that are on screen and drops the rest from fresh, so it never polls. A draw already in flight when a mark arrives is marked again when it lands. A page may still refresh on a clock: it declares `every`, which the Server clamps as ADR-0037 clamps a Query's interval and sends with each of the page's answers rather than once with its patterns, so a reloaded Plugin's new interval reaches an App already showing the page. The App keeps the clock while the page is on screen, naming its hash as for any draw, and the Server reads again the Queries older than the interval, so a redraw with nothing new answers `unchanged`.
- **The App owns UI state.** Search text, selection, expansion, scroll, drafts, open sheets and pending states belong to kit components, as ADR-0031 began. Optimistic state is the one exception the kit cannot guess: an Operation call may name nodes of the tree and the props they show while it runs, the App shows them at once, and puts the tree back with an error toast when the Operation fails. What a page must remember to draw differently, such as a tab, a range or a page size, is Page state: declared with defaults by the page, kept by the App, and part of the page's address, so changing it fetches that page again. A search or a selection the loader needs is Page state the render binds, and the App changes it once the edits pause. A paged list is the kit's: the page's `list` reads one page from a cursor, Argo keeps each page as a Query of the address and its cursor, and the App says how many it shows, outside the address, so a load more reads only the next page and a pull reads the first again.
- **Live pages are the one tree stream.** A page whose loader yields over time, such as a log tail, keeps a subscription, and only it. The stale marks above are a second subscription, one per App, that carries a Plugin and the addresses it marks, and never a tree. The Server coalesces its answers to one per frame and sends the first whole, or `unchanged` against the hash the App keeps, and each after as ADR-0031's keyed patches from the tree sent before, naming that tree's hash so an App that kept another subscribes again. A live page is drawn only by its subscription: stale marks and its clock do not draw it, a draw that is not a subscription answers its first value, and it has no paged list. The subscription lasts while the page is on screen; leaving it, or the Plugin stopping, ends the loader.
- **Queries stay; `useData` goes.** ADR-0037's Query is a described read or a named read that Argo performs, dedups and caches, and it is the one cache of a Plugin's reads. A loader reads Queries with `read`, or awaits any `argo` read directly when it needs no cache. A background pass runs a page's loader for one Project and discards the answer, instead of mounting the page headless.

## Slots

- **Items Slots are unchanged.** ADR-0046's items Slots (Project details, Session row meta, Activity, Session bar) still answer items, not trees, and Argo keeps each answer per worker generation.
- **Workbench card pages are Loader pages.** The `page` and `tab` of an `argo/session/workbench/v1` card are drawn by the same path as any page, at their Page address with the Session's `projectId` and `sessionId` as context. Argo's card frame stays Argo's; only what fills it changes.
- **Replaceable Slots answer once.** ADR-0027's `ui.render` Hook returns a tree from a pure render, with Component events as values (`ctx.to.go`, `ctx.to.run`). The Server checks it as it checks a page's tree and answers the App once, with no view and no subscription. Core draws its own when the tree is refused, throws or needs a newer App than the one asking, and the Server logs why. New core props ask again.
- **A background pass runs the Loader alone.** On its interval the Server runs the background page's `load` for one Project, with no render, no tree and no mounted view, within the same sixty-second budget.
- **One change signal.** `argo.changed()` replaces `argo.pages.stale()` and `argo.slots.changed(slotId)`: it makes every Query the Plugin keeps due, its paged-list pages among them, marks the Plugin's pages stale, and drops the items-Slot answers Argo keeps, so open lists ask again. An Operation run does the same.

## Considered options

- **Keep the reconciler and finish Spec 0026's steps 2 to 4.** Rejected: it keeps two trees in step across a network for every page, and the cost recurs with each kit component and screen.
- **Plugins send data into screens Argo designs,** as VS Code's tree views and Airbnb's server-driven UI do. Rejected for now: every new layout would need an App release, and ADR-0025 already turned down Plugins as data providers.
- **Run Plugin JavaScript in the App.** Rejected as ADR-0025 rejected it: phones may not run downloaded code.
- **Operations only for Agents, with lighter UI-only actions.** Rejected: two write paths, and a write a person can make that an Agent cannot breaks ADR-0044's rule that whatever a user can do, an Agent can.
- **A payload mapping on each call,** as `to.run(name, args, { from: { card: 'id' } })` beside a second mapping for Page state. Rejected for one payload value that goes wherever `to.set` or `to.run` takes a value: one thing to learn instead of two, and fixed and reported values mix in one object. Spreading the whole payload into an Operation's params was rejected too, since its fields would have to be named as the params are and every field declared.
