# Agents run on subscription logins through ACP

Argo runs Sessions on the subscription the user already pays for: no Anthropic API key and no `OPENAI_API_KEY`. Spec 0009 replaces Argo's native protocol adapters with registry-discovered upstream ACP adapters behind the public ACP SDK (owner, 2026-10-09). Spec 0009 #359 removes the native package and its remaining consumers (owner, 2026-10-13). Registry metadata and SQLite selections are the catalog and launch authorities. Retained artwork lives under `packages/engine/src/agents/assets`; it supplies no second static catalog.

Engine owns each effective Agent launch and its SDK connection. Compatible Sessions within one Project share startup; distinct Projects or executable/version/arguments/environment/authentication contexts stay isolated. Process cwd is the Project root, and each new/load/resume request carries its own Checkout cwd. Launch inputs are captured before startup; private reuse keys contain only these effective fields. Session receives one owned SDK role/identity lease. Ordinary methods remain SDK-direct. Shared code branches on protocol capabilities, never on a vendor name. Claude and Codex Sessions draw the same UI.

A broken shared connection is that connection's failure, not one Session's. Engine removes it from reuse, fences its callbacks and question answers, informs each attached Session once, and terminates its process. Concurrent recoveries share one replacement startup. Startup may overlap the old process's termination, but resuming a Session or starting work in an affected Checkout waits for the old process's observed exit; an exit not observed within five seconds of the failure blocks recovery in that Checkout with a concrete error. A replacement that fails to start or resume counts as another crash. Each Session keeps the existing one-second minimum retry delay and three-crashes-in-ten-minutes budget, and never resends a prompt whose delivery became uncertain: the Turn ends as interrupted and the Feed says its output may be missing (owner, 2026-10-09, #345). Descendant containment across Engine death belongs to the Supervisor and is not proved here.

Both subscription sign-in paths use ACP setup. Missing authenticated upstream compatibility and lifecycle checks remain explicit gates under #360 (owner, 2026-10-13). The empty Session lifecycle slice proves generic ownership, not authenticated upstream isolation, descendant cleanup, or process-count savings. Agents without independent ACP session closure fail the shared lifecycle capability check.

Argo enforces the subscription rule only on what an Agent reports (owner, 2026-10-14, #605). An Agent that reports its account through ACP authentication status must report a subscription, or it is Account not supported. An Agent that reports no account, as OpenCode and Gemini CLI do, is Ready and opens Sessions; when it answers opening a Session or a prompt with ACP `auth_required`, Argo saves its Readiness as Sign-in needed and shows the error. Argo cannot prove such an Agent runs on a subscription, and refusing every Agent that stays silent would make most Registry Agents unusable.

## Considered Options

- Argo-owned native adapters. Superseded by Spec 0009: public upstream adapters and the SDK own protocol behavior.
- Refusing Agents that do not report their account. Rejected (#605): ACP has no standard account report, so it blocked Agents that sign in on their own, with no way for the user to fix it.
- Off-the-shelf ACP adapters. Rejected earlier because paged history, Subagents and usage were incomplete; Spec 0009 accepts upstream protocol support and defines honest product outcomes for unavailable capabilities instead of maintaining another native strategy.
