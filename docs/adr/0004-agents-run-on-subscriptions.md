# Agents sign in through ACP

Argo signs in to an Agent the way Zed does (`c403bc6`): it offers the methods the Agent lists in `initialize`, in the Agent's order, and runs the one the user picks. An `agent` method is ACP `authenticate`; a `terminal` method runs the Agent's command with the method's args and env in a terminal the Engine owns. Argo filters methods by nothing but those two types. It checks no subscription or account: the Agent says when it needs sign-in by answering `auth_required`, on an open or on a Turn, and Argo then offers its methods. There is no readiness gate before a Session opens (#717). Spec 0009 replaced Argo's native protocol adapters with registry-discovered upstream ACP adapters behind the public ACP SDK (owner, 2026-10-09; native package removed under #359). Registry metadata and SQLite selections are the catalog and launch authorities. Retained artwork lives under `packages/engine/src/agents/assets`; it supplies no second static catalog.

Only the vendor module, `packages/engine/src/agents/vendor.ts`, branches on a vendor. It clears `ANTHROPIC_API_KEY` for the Registry Agent `claude-acp`, so Claude runs on the user's subscription (owner, 2026-10-15, #717). It also holds Zed's `claude-login` output patterns, which finish that terminal sign-in before the program exits. Everywhere else branches on negotiated ACP capabilities; the oxlint `vendor-name` rule enforces this.

Owner amendment, 2026-10-19: the vendor module normalizes the Registry Agent `grok-build` initialization to advertise image prompts. The installed Grok 1.0.62 reports `image: false`, while its published ACP parser accepts image blocks; [independent live verification](https://github.com/phuryn/grok-build-vscode/blob/main/research/vision-input.md) documents this mismatch. All other capabilities and Agents retain their negotiated values. Engine integration tests supply the contradictory handshake and verify image bytes reach ACP for Grok while another Agent is rejected. These tests do not establish live model vision; remove this compatibility override when supported Grok releases reliably advertise image support.

Configuration discovery before Send also surfaces the Agent’s `auth_required` or launch failure in the Composer tray (owner, 2026-10-19). Its sign-in completion and Retry repeat discovery without creating an Argo Session or sending a prompt.

A sign-in belongs to one Agent and Project. Every App watching them sees it pending and can cancel it, and its finish runs the open again. A sign-in after a Turn ended `auth_required` only clears that card; the user resends. Closing a terminal method's terminal before its command exits cancels the sign-in, which counts as a failure.

Owner amendment, 2026-10-28 (#1295): a Session with Agent access to Argo owns its ACP process and connecting promise. Its process receives that Session's `ARGO_TOKEN` and the `argo` CLI on `PATH`; closing the Session revokes its token. ACP supplies environment variables when a process starts, so Sessions sharing a process cannot receive distinct tokens. Tokens must never identify a sibling Session.

Sign-in and configuration discovery still share one connecting promise per Agent and Project. They receive no Session token. Sessions without Agent access may share that process until removal, save, a newer Registry version, Retry, exit, or Engine shutdown. Sign-in remains shared across the Agent and Project; separate Session processes do not create separate sign-in flows.

The Agent runs through `$SHELL -c` in the Engine process group. Its environment comes from the Project main Checkout's login shell and is cached for the Engine's life. Launch extras apply next, then the vendor module's. Argo supplies the Session's CLI path and token only to its own process.

A process exit ends each active Turn using that process with `error` and an exit Notice containing the final contiguous stderr block. The Server collects stderr for up to 250 ms after exit. It closes those Sessions and forgets the connection. An open that fails shows Failed to Launch with Retry, which opens the Session again without a Turn. An open that never reached the Server, because the Connection dropped, shows the "Couldn't open the Session" toast instead, and opens again when the Connection reopens. The next Send uses `session/resume`; there is no automatic reopen, retry delay or crash budget.

The Server accepts protocol version 1 or newer. `session/close` is optional. Close sends it when advertised, then drains under the five-second deadline. Error or timeout logs and releases the Agent session. Closing one Session does not kill a shared process. A process owned by one Session stops when that Session closes, including a failed or cancelled open. Missing authenticated upstream checks remain explicit gates under #360. Scripted tests prove Argo's supplied scenarios, not authenticated upstream compatibility or descendant containment across Engine death.

## Considered Options

- A subscription or account check before a Session opens. Rejected: Zed has none, and the Agent's own `auth_required` is the only reliable signal.
- Filtering methods to the ones Argo prefers. Rejected: the Agent's list and order are its own; Argo shows every `agent` and `terminal` method.
- Argo-owned native adapters. Superseded by Spec 0009: public upstream adapters and the SDK own protocol behavior.
- Off-the-shelf ACP adapters. Rejected earlier because paged history, the Agents a Session starts and usage were incomplete; Spec 0009 accepts upstream protocol support and defines honest product outcomes for unavailable capabilities instead of maintaining another native strategy.
