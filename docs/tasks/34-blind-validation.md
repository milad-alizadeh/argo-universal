The pagination failure was reproduced at 1000 × 900 in both themes. Open the original On End Reached showcase, put the pointer inside the list, wheel down 10000 px once, and wait 250 ms. The old list viewport was y24..504, scrollTop 720, and new scrollHeight 1296. The 20 px progressbar was y514..534, entirely clipped. Another 300 px wheel made it visible at y418..438. The original failure screenshots are `pagination-first-light-1.png` and `pagination-first-dark-1.png`; `pagination.json` records the measurements. On the renamed build the same first gesture moves scrollTop to 816 and the spinner is already y418..438. `pagination-replay.json` and `pagination-final-assertions.json` record the replay. This is a fixed failure, not an untested implementation claim.

Two test-timing problems were also found. The screen ScrollFade play function still asserted the superseded fade toggling behavior; the implementation agent changed it to fixed fades. The independent three-file Vitest run then returned 27 passed / 1 failed: Search synchronously expected focus before the component's requestAnimationFrame focus ran. Actual raw keyboard/focus checks pass at the observable focused state. The implementation agent changed the test to await that state; rerunning the exact Search test returned 1 passed / 13 skipped. Neither test correction was silently made by this validator.
