# Screens

- `packages/client/src/screens/` mirrors `apps/universal-app/src/app/`: one folder per route. A route file is a one-line shell that reads its params and renders its screen from `@repo/client`.
- Name screens and views `<entity>-<list|detail|new|edit>-{screen,view}` (`CODING_STANDARDS.md`).
- A dynamic segment's folder is `$param`, never `[param]`: `app/sessions/[id].tsx` renders from `screens/sessions/$id/`. Oxlint overrides and `tooling/oxlint/kit-styling-allowlist.json` read path patterns as globs, where `[id]` is a character class that never matches the folder.
- Every page declares its header once, through the kit `Screen` (ADR-0043): its title, Back, search and Actions become the native stack header on a phone and its own heading when wide. A section's root is a `Screen` too, its `SectionList.rootPage` (`screens/section-lists.tsx`). There is no second header vocabulary in the client. Session pages, whose body is not a `Screen`, declare the header with the kit-only `ScreenStackHeader` (the Screen's header and navigation, no heading or body) in the screen, never the view.
- ☰ is not a prop. The App wraps a narrow root in a `ScreenMenuContext` provider (`{ onOpen, badge }`, kit-only, never on the Plugin wire), and the `Screen` draws ☰ when the provider is present and the window is narrow. The provider marks the root: never infer it from `canGoBack()`, or a deep-linked page would show ☰ instead of Back.
- `ScreenStack` (`navigation/section-stack.tsx`) only composes stacks; its `title` is a fallback for the root until its Screen mounts. A Plugin's catch-all `[...path]` route renders from `screens/plugins/$path/`; while the Plugin list loads it renders `<ScreenStackHeader title="" />`, so the page always has a way out.
