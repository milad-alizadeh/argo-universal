# First-Turn adapter

`connect` owns one `codex app-server --listen stdio://` process for the Session. It initializes the protocol, verifies ChatGPT subscription authentication, reads the model catalog, and starts or resumes the stored vendor session. Model and effort defaults come from that catalog. Config changes are sent with the next prompt; cancellation uses the active vendor Turn id. Closing ends stdin and waits for process exit, with bounded termination if the CLI does not exit.

The Session supplies Argo Turn ids. `connect` tracks the corresponding active vendor id returned by `turn/start` or announced by `turn/started`, including a notification arriving before its RPC response. Inherited API key variables are removed from the child environment. The pure `toAgentEvents` converter emits changes without a Session or Turn envelope; the Session and Feed add those fields. A resumed Turn derives its cumulative usage baseline from its first usage update when the previous total is unavailable. Final item records replace their streamed rows, and an interrupted or failed Turn settles any unfinished Tool calls. Vendor user-side items are dropped because the Session already stores the human prompt (ADR 0012).

`protocol.gen.ts` contains the types exported by Codex CLI 0.157.0, bundled with their dependencies. Run `node packages/agents/codex/generate-protocol.ts` with that CLI on PATH to regenerate it. The generator renames colliding legacy type names and leaves their shapes intact. The [official app-server documentation](https://learn.chatgpt.com/docs/app-server) describes these version-specific exports. As ADR 0015 requires, vendor payloads use these types and every Feed change is validated, rejected, logged and counted at the existing Feed boundary.

This issue covers text prompts, messages, thoughts, file edits, commands, usage, cancellation, resume and stop. Request answers, Plan proposals, images, titles, Subagents, Shell controls and external continuation detection belong to later milestone slices. Unsupported server requests receive a protocol error so they do not wait indefinitely. Command actions and duration remain in the Tool call's raw data until the Feed contract slice adds their presentation fields.
