# First-Turn adapter

`connect` owns one `codex app-server --listen stdio://` process for the Session. It initializes the protocol, verifies ChatGPT subscription authentication, reads the model catalog, and starts or resumes the stored vendor session. Model and effort defaults come from that catalog. Config changes are sent with the next prompt; cancellation uses the active vendor Turn id. The Agent machine's cancellation signal closes the CLI even during initialization or a pending prompt. Closing ends stdin and waits for process exit, with bounded termination if the CLI does not exit.

The Session supplies Argo Turn ids. `connect` keeps one record for the active vendor Turn, whose id comes from `turn/start` or `turn/started`. Cancellation waits for that identity. A matching `turn/completed` releases a pending prompt, and late responses cannot replace the next Turn's identity. Inherited API key variables are removed from the child environment. The pure `toAgentEvents` converter emits changes without a Session or Turn envelope; the Session and Feed add those fields. A resumed Turn derives its cumulative usage baseline from its first usage update when the previous total is unavailable. Final item records replace their streamed rows, and an interrupted or failed Turn settles any unfinished Tool calls. Vendor user-side items are dropped because the Session already stores the human prompt (ADR 0012).

`protocol.gen.ts` contains the types exported by Codex CLI 0.157.0, bundled with their dependencies. Run `node packages/agents/codex/generate-protocol.ts` with that CLI on PATH to regenerate it. The generator renames colliding legacy type names and leaves their shapes intact. The [official app-server documentation](https://learn.chatgpt.com/docs/app-server) describes these version-specific exports. As ADR 0015 requires, vendor payloads use these types and every Feed change is validated, rejected, logged and counted at the existing Feed boundary.

The adapter covers text prompts, messages, thoughts, file edits, commands, Compaction, usage, Permission requests, question Elicitations, cancellation, resume and stop. Plan proposals, titles, Subagents, Shell controls and external continuation detection belong to later milestone slices. Unsupported server requests receive a protocol error so they do not wait indefinitely. Agent-supplied command actions and notification timestamps are exposed in `_meta.argo`; an absent action list is omitted, and an `unknown` action stays unknown.

Request answers follow the installed Codex desktop app's behavior, as requested for issue #57. Deny sends `decision: "decline"`; the protocol and desktop approval panel offer no feedback text. The adapter registers `permissionFeedback: false`, so the Server rejects a Deny message before consuming the request. Accepted question answers map each supplied field to its string answers; skipped questions remain absent. Decline sends an empty answer map. Cancelling a blocking question interrupts its Turn; cancelling a nonblocking question sends an empty answer map. Requests have no deadline and replies keep the original server request id. This behavior was verified against the installed desktop app's approval and question handlers (app version 26.928.31416) and CLI 0.157.0 generated protocol types.

The transport stamps each notification with its receipt time. Conversion remains pure, and a Tool call that never sends a final item receives its end time when the Turn ends. Typed response mocks supply deterministic receipt times for pure translation tests.

## Updating the provider contract

Run `node packages/agents/codex/generate-protocol.ts` against the upgraded CLI to refresh its official protocol types. Response fixtures satisfy these types; incompatible shapes fail type checking. Unit tests pass those fixtures through the real pure mapper and compare independent expected Argo events, without CLI processes or transport stubs.

`pnpm install` generates the ignored production decoder artifacts from the checked-in protocol types with `ts-json-schema-generator`. Package type checking and tests regenerate them too. Ajv decodes raw production responses and consumed notifications once at the transport boundary. App bundlers include the imported decoder data. No provider process or network is needed to generate these artifacts. Generated schemas are build output and are never committed.

App E2E uses shared Argo fixtures at the Agent adapter port (ADR-0018). Updating protocol types does not automatically update semantic expectations or the App fixtures.
