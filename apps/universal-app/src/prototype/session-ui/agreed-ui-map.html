  1. L1
    The app has one Expo Router tree. At 720 px or wider it draws the desktop shell, and below that it draws the phone. The same URL opens the same thing on both.
  2. L2
    On a phone, a left drawer holds the sections: Sessions, Issues, Atlas and Settings. It opens from ☰ or by swiping from the left edge. Sessions has a badge that counts the Sessions waiting for input.
  3. L3
    Each section opens on its list, which is the desktop sidebar's list drawn full screen. The list has a title with ☰ on the left and search and filter icons on the right.
  4. L4
    On a phone, detail screens push full screen over the drawer with a back chevron, and iOS also lets you swipe back from the edge. The detail screens are Session, New Session, Issue view, Issue, New Issue, Atlas resource, Project settings and Accounts.
  5. L5
    The desktop follows old Argo's layout:· an icon rail with the sidebar toggle at the top, then Sessions, Issues and Atlas, and Settings at the bottom
    · a list sidebar
    · the detail pane
    · a right inspector    Confirm each piece with the owner before copying anything from the old app.
  6. L6
    On the desktop, each section root opens a detail next to its list:· Sessions opens the first active Session
    · Issues opens the "All open" view
    · Atlas opens the first resource
    · Settings opens Accounts
  7. L7
    When a web or Electron window crosses 720 px, the shell swaps and the URL stays. On a phone, the open detail screen has a back stack that returns to its section list.
S · lists

Every section list has the same shape

Sessions, Issues, Atlas and Settings draw the same list in the desktop sidebar and on the phone's section screen.

  1. S1
    The list starts with a title row, followed by search and filter as icons. Search opens in place of the title. The filter opens a popover.
  2. S2
    Rows are grouped under Projects. A "Projects ⋯ +" sub-header stays expanded. Its + adds a Project, and its ⋯ collapses or expands all Projects. The flat lists are gone.
  3. S3
    Each Project has a plain heading:· tapping the heading collapses it, and a collapsed heading shows its count
    · its ⋯ opens that Project's settings: hover shows it on the desktop, long-press opens it on a phone
    · headings have no + of their own
    · an empty Project keeps its heading unless search or the archive filter narrows the list
  4. S4
    The Sessions filter switches between Active and Archived.
  5. S5
    Issues has "All open" above the Projects sub-header, and it groups its Issues by Project. A Project's views group by the tracker's status. A Project without a tracker shows "Set up Issues…", which goes to that Project's settings. The views come from each tracker Integration, Linear or GitHub.
  6. S6
    New work starts from one floating round write button on the Sessions and Issues lists. On a phone it sits at the bottom right. On the desktop it sits at the bottom left of the sidebar. Its size and look need proper design.
  7. S7
    Settings has four groups:· Projects: each Project with its tracker, plus Add Project
    · Server: Accounts and Connection
    · Agents: Claude and Codex
    · App: Appearance and Notifications    On the desktop this list sits in the sidebar.
P · Session screen

The Session screen

  1. P1
    The phone header keeps only four things: back, the status mark with the title, a Plan button showing done out of total when a Plan exists, and ⋯. The ⋯ menu holds Changed files · n, Rename and Archive.
  2. P2
    The desktop header shows:· the title and its state (click the title to rename)
    · the checkout path · branch
    · the Subagents and Shells buttons
    · the Changed files chip
    · ⋯
    · the inspector toggles
  3. P3
    The bottom of the Session shows exactly one of three things:· the composer
    · a Permission request or Elicitation card in place of the composer
    · an "Archived · read-only" banner
  4. P4
    On the desktop, the Plan is a sticky panel at the top of the Feed. On a phone it opens as a popover from the header's Plan button.
  5. P5
    Changed files: on the desktop, the chip opens the file list in the right inspector, which can expand to the full width. On a phone, ⋯ → Changed files opens a popover.
  6. P6
    Subagents and Shells are old Argo's two buttons, each with a count that is green while anything runs and grey once all have ended. Each button opens a list grouped into Running and Finished, and each row shows model · duration · tokens.· on the desktop the buttons sit at the top right of the header, and an item opens in the right inspector
    · on a phone they are pills above the composer, and an item opens in a native page sheet
    · a Subagent row in the Feed opens the same place
  7. P7
    Archiving a Session that has uncommitted files asks first. Archiving shows a toast with Undo, and the branch is kept.
O · overlays

Popovers everywhere, for now

  1. O1
    Menus, filters, pickers, confirmations and Add Project open as a popover on every platform, anchored to the button that opened it. This applies to phones too, for now.
  2. O2
    No bottom sheets on a phone. The Subagents and Shells list is a popover like every other one.
  3. O3
    A full view that belongs to a Session opens as a native page sheet on a phone, not as a pushed screen. That covers a Subagent's Feed and a Shell's output. Android and narrow web show it full screen.
N · new work

Starting a Session or an Issue

  1. N1
    The New Session page has Codex-style "Start the Session in" rows for Server and Project above the composer. Server has one entry until the app supports more machines. The composer holds the Agent, model, mode, effort and checkout (worktree from a branch, or local). The desktop shows the heading "What should we work on?".
  2. N2
    New Issue uses the same "Create the Issue in" rows, and lists only Projects that have an Issue tracker.
  3. N3
    Sending replaces the New page with the new Session or Issue, so going back returns to the list, not to an empty form.

R · folders

Folder structure

ADR 0009 says route files in the app only render a screen, and screens, components and tRPC live in @repo/client. The trees below follow that. Layouts own the navigators, and the client package draws what goes inside them.

  1. R3
    Two Expo Router groups carry the layout: (app) picks the shell by width, and (sections) is the phone drawer. Detail routes sit beside (sections), so on a phone they push over the drawer. Storybook stays outside the shell.
  2. R4
    Layout files own the navigators (Stack, Drawer, Slot) and render the shell pieces from @repo/client. Route files stay one-liners that render a screen, as ADR 0009 requires.
  3. R5
    @repo/client stays free of expo-router. Screens move through a useNavigate() context with typed destinations, such as { to: 'session', id }. The app fills that context from expo-router, and Storybook fills it with a recorder that play functions can assert on.
  4. R6
    Components are grouped by feature under components/. File names stay PascalCase as in the client package today, and each feature folder holds its own stories.
  5. R7
    Components adapt with useWide(). They split into separate phone and desktop components only where the two trees really differ: the Session header, the shell, and the list screen frame.
X · scope

Scope and terms

  1. X1
    Atlas resources are diagrams and maps of the code. They are not scoped yet, so build nothing for them beyond the placeholder list.
  2. X2
    Keep the Shells button and add the term to GLOSSARY.md:Shell: a command an Agent started in the background, which keeps running while the Turn goes on. Avoid: background task, terminal, process.
  3. X3
    React Native Reusables primitives replace the prototype's hand-made ones. This is the implementer's job, not part of the prototype.
  4. X4
    ADR 0010. The prototype's Feed fixtures are hand-written. Real stories use recorded vendor sessions, so the Feed parts need recordings first.
